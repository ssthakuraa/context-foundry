# Market and technical landscape

**Status:** Draft

This is the initial broad landscape, not an exhaustive current competitor audit.
The bounded primary-source synthesis and competitive confidence assessment are in
[design closeout](design-closeout.md). Do not infer uniqueness from this category list.

Public offerings from large consulting firms commonly combine AI-assisted
reverse engineering, dependency discovery, knowledge repositories, target
architecture, code transformation, testing, migration, and managed delivery.
They generally package these capabilities as proprietary platforms and
services.

ContextFoundry should occupy a narrower open-source position: the governed
engineering-context and verification layer that can feed existing coding
agents, consulting accelerators, and enterprise delivery systems.

## Adjacent capabilities

- Software catalogs provide ownership and service metadata.
- Code-intelligence systems provide search, symbol navigation, and dependency
  context.
- Static-analysis systems provide language- or security-specific facts.
- Refactoring systems perform deterministic code transformation.
- AI coding agents perform investigation, reasoning, and code generation.

ContextFoundry connects these categories through product-owned terminology,
evidence, policy, architecture proposals, and test-impact relationships.

## Differentiation hypothesis

The open-source opportunity is not to reproduce an entire modernization
factory. It is to provide a portable and reviewable context substrate with:

- Enterprise-owned portable releases with Git-suitable configuration/metadata
- First-party extraction adapters and open agent interfaces, not mandatory external context providers
- Source- and revision-bound provenance
- Policy-aware retrieval
- Architecture and test-impact views
- Agent-neutral interfaces
- Reproducible evaluation
