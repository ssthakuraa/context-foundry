# Reference analysis

**Status:** Draft

Historical orientation only. [CF-0.2 closeout](design-closeout.md) and the
[requirements](../requirements/product-requirements.md) govern current design scope.

The detailed [v2 disposition](v2-disposition.md) supersedes this initial note for
carry-forward/adapt/rework decisions. V2 supplies substantial reusable design ideas;
its failed end-to-end evaluation primarily motivates controlled retrieval/content/
directive experiments, not discarding preparation without evidence.

The initial product thinking was informed by an existing Engineering Knowledge
Pack reference design. That material is an input to product discovery only.

ContextFoundry is an independent product and should not inherit the reference
project's name, acronym, source-specific terminology, implementation choices,
or undocumented assumptions.

## Ideas worth evaluating

- Versioned product-owned engineering context
- Deterministic extraction and rebuildable serving projections
- Provenance and completeness diagnostics
- Bounded graph and search retrieval
- Agent-directed progressive investigation
- Human review of scope and proposed conclusions
- MCP and CLI as interchangeable delivery interfaces

## Ideas not adopted automatically

- Reference-project-specific artifact kinds
- Reference-project-specific source systems or product terminology
- Fixed context-size or file-count rules
- Any claim of universal productivity improvement
- Any architecture decision that depends on a particular coding agent

The ContextFoundry documentation and contracts are the authoritative product
definition once they are accepted.
